# Deploy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Desplegar control-actions en un VPS con Docker Compose (postgres + api + nginx), TLS automático con Let's Encrypt, y un pipeline CI/CD con GitHub Actions que despliega en cada push a `main`.

**Architecture:** Nginx termina TLS y sirve el SPA estático de `frontend/dist/` copiado durante el CI. El contenedor `api` (Fastify) corre internamente y ejecuta migraciones Prisma al arrancar. PostgreSQL usa un volumen persistente en el host. Todo orquestado con Docker Compose.

**Tech Stack:** Docker · Docker Compose · Nginx · Certbot (Let's Encrypt) · GitHub Actions · PostgreSQL 16 Alpine

---

## Prerrequisitos

- VPS con Ubuntu 22.04+ (mínimo 1 vCPU, 1 GB RAM)
- Dominio apuntando a la IP del VPS (registro A configurado)
- Repositorio en GitHub con acceso a GitHub Actions
- Puerto 22 (SSH), 80 y 443 abiertos en el firewall del VPS

## Task 1: Dockerfile del backend

**Files:**
- Create: `Dockerfile.backend`

- [ ] **Step 1: Crear Dockerfile.backend**

```dockerfile
# Dockerfile.backend
# Stage 1: build
FROM node:20-alpine AS builder
WORKDIR /app

# Copiar manifiestos del monorepo y del backend
COPY package.json package-lock.json ./
COPY shared/package.json ./shared/
COPY backend/package.json ./backend/

# Instalar solo dependencias de producción del backend
RUN npm ci --workspace=backend --workspace=shared

# Copiar código fuente
COPY shared/ ./shared/
COPY backend/ ./backend/

# Compilar TypeScript
WORKDIR /app/backend
RUN npx tsc

# Generar cliente Prisma
RUN npx prisma generate

# Stage 2: imagen final
FROM node:20-alpine AS runner
WORKDIR /app

ENV NODE_ENV=production

# Copiar artefactos compilados
COPY --from=builder /app/backend/dist ./dist
COPY --from=builder /app/backend/prisma ./prisma
COPY --from=builder /app/backend/node_modules ./node_modules
COPY --from=builder /app/shared ./shared

# Prisma CLI para ejecutar migraciones
COPY --from=builder /app/node_modules/.bin/prisma /usr/local/bin/prisma

EXPOSE 3000

CMD ["sh", "-c", "npx prisma migrate deploy && node dist/server.js"]
```

## Task 2: Configuración de Nginx

**Files:**
- Create: `nginx/nginx.prod.conf`

- [ ] **Step 1: Crear nginx/nginx.prod.conf**

```nginx
# nginx/nginx.prod.conf
server {
    listen 80;
    server_name TU_DOMINIO.COM;

    # Redirect HTTP → HTTPS
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    server_name TU_DOMINIO.COM;

    # Certificados gestionados por Certbot
    ssl_certificate     /etc/letsencrypt/live/TU_DOMINIO.COM/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/TU_DOMINIO.COM/privkey.pem;
    include             /etc/letsencrypt/options-ssl-nginx.conf;
    ssl_dhparam         /etc/letsencrypt/ssl-dhparams.pem;

    # Gzip
    gzip on;
    gzip_types text/plain application/javascript text/css application/json;

    # SPA: archivos estáticos
    root /usr/share/nginx/html;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    # Proxy a la API
    location /api/ {
        proxy_pass         http://api:3000/api/;
        proxy_http_version 1.1;
        proxy_set_header   Host              $host;
        proxy_set_header   X-Real-IP         $remote_addr;
        proxy_set_header   X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto $scheme;
    }
}
```

- [ ] **Step 2: Crear docker-compose.prod.yml**

```yaml
# docker-compose.prod.yml
services:
  postgres:
    image: postgres:16-alpine
    restart: unless-stopped
    env_file: .env.prod
    volumes:
      - pgdata:/var/lib/postgresql/data
    networks:
      - internal
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U $$POSTGRES_USER -d $$POSTGRES_DB"]
      interval: 10s
      timeout: 5s
      retries: 5

  api:
    image: ghcr.io/GITHUB_USER/control-actions-api:latest
    restart: unless-stopped
    env_file: .env.prod
    depends_on:
      postgres:
        condition: service_healthy
    networks:
      - internal
    # No expone puertos al exterior — solo accesible por Nginx internamente

  nginx:
    image: nginx:alpine
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./nginx/nginx.prod.conf:/etc/nginx/conf.d/default.conf:ro
      - ./frontend/dist:/usr/share/nginx/html:ro
      - certbot-certs:/etc/letsencrypt:ro
      - certbot-www:/var/www/certbot:ro
    depends_on:
      - api
    networks:
      - internal

  certbot:
    image: certbot/certbot
    volumes:
      - certbot-certs:/etc/letsencrypt
      - certbot-www:/var/www/certbot
    # Solo se ejecuta manualmente para obtener/renovar certificados
    profiles: ["certbot"]

volumes:
  pgdata:
  certbot-certs:
  certbot-www:

networks:
  internal:
    driver: bridge
```

## Task 5: Pipeline CI/CD con GitHub Actions

**Files:**
- Create: `.github/workflows/deploy.yml`

- [ ] **Step 1: Configurar GitHub Secrets en el repositorio**

En GitHub → Settings → Secrets and variables → Actions, añadir:

| Secret | Valor |
|--------|-------|
| `VPS_HOST` | IP del VPS |
| `VPS_USER` | usuario SSH |
| `VPS_SSH_KEY` | clave privada SSH (sin passphrase) |
| `GHCR_TOKEN` | GitHub Personal Access Token con `write:packages` |

Para generar la clave SSH sin passphrase:
```bash
ssh-keygen -t ed25519 -C "github-actions" -f ~/.ssh/github_actions -N ""
cat ~/.ssh/github_actions      # → pegar como VPS_SSH_KEY en GitHub
cat ~/.ssh/github_actions.pub  # → añadir al authorized_keys del VPS
```

En el VPS:
```bash
echo "CONTENIDO_DE_github_actions.pub" >> ~/.ssh/authorized_keys
```

- [ ] **Step 2: Crear .github/workflows/deploy.yml**

```yaml
# .github/workflows/deploy.yml
name: Build & Deploy

on:
  push:
    branches: [main]

jobs:
  test-backend:
    name: Test backend
    runs-on: ubuntu-latest
    services:
      postgres:
        image: postgres:16-alpine
        env:
          POSTGRES_DB: control_actions_test
          POSTGRES_USER: test
          POSTGRES_PASSWORD: test
        options: >-
          --health-cmd pg_isready
          --health-interval 10s
          --health-timeout 5s
          --health-retries 5
        ports:
          - 5432:5432
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: '20', cache: 'npm' }
      - run: npm ci
      - name: Run backend tests
        working-directory: backend
        env:
          DATABASE_URL: postgresql://test:test@localhost:5432/control_actions_test
          TEST_DATABASE_URL: postgresql://test:test@localhost:5432/control_actions_test
          JWT_SECRET: test-secret-at-least-32-characters-long
          JWT_REFRESH_SECRET: test-refresh-secret-at-least-32-chars
        run: |
          npx prisma migrate deploy
          npm test

  build-backend:
    name: Build & push backend image
    needs: test-backend
    runs-on: ubuntu-latest
    permissions:
      contents: read
      packages: write
    steps:
      - uses: actions/checkout@v4
      - uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}
      - uses: docker/build-push-action@v5
        with:
          context: .
          file: Dockerfile.backend
          push: true
          tags: |
            ghcr.io/${{ github.repository_owner }}/control-actions-api:latest
            ghcr.io/${{ github.repository_owner }}/control-actions-api:${{ github.sha }}

  build-frontend:
    name: Build frontend
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: '20', cache: 'npm' }
      - run: npm ci
      - name: Build SPA
        working-directory: frontend
        run: npm run build
      - uses: actions/upload-artifact@v4
        with:
          name: frontend-dist
          path: frontend/dist/
          retention-days: 1

  deploy:
    name: Deploy to VPS
    needs: [build-backend, build-frontend]
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/download-artifact@v4
        with:
          name: frontend-dist
          path: frontend/dist/
      - name: Copy frontend dist to VPS
        uses: appleboy/scp-action@v0.1.7
        with:
          host: ${{ secrets.VPS_HOST }}
          username: ${{ secrets.VPS_USER }}
          key: ${{ secrets.VPS_SSH_KEY }}
          source: "frontend/dist/"
          target: "/srv/control-actions/"
      - name: Deploy via SSH
        uses: appleboy/ssh-action@v1.0.3
        with:
          host: ${{ secrets.VPS_HOST }}
          username: ${{ secrets.VPS_USER }}
          key: ${{ secrets.VPS_SSH_KEY }}
          script: |
            cd /srv/control-actions
            echo ${{ secrets.GITHUB_TOKEN }} | docker login ghcr.io -u ${{ github.actor }} --password-stdin
            docker compose -f docker-compose.prod.yml pull api
            docker compose -f docker-compose.prod.yml up -d
            docker compose -f docker-compose.prod.yml exec -T api sh -c "npx prisma migrate deploy" || true
            docker image prune -f
            echo "Deploy completado: $(date)"
```

## Task 6: Backup automático de la base de datos

- [ ] **Step 1: Crear script de backup en el VPS**

```bash
cat > /srv/control-actions/scripts/backup-db.sh << 'EOF'
#!/bin/bash
BACKUP_DIR="/srv/backups/control-actions"
DATE=$(date +%Y%m%d_%H%M%S)
mkdir -p "$BACKUP_DIR"

docker compose -f /srv/control-actions/docker-compose.prod.yml exec -T postgres \
  pg_dump -U control_actions_user control_actions \
  | gzip > "$BACKUP_DIR/db_$DATE.sql.gz"

# Mantener solo los últimos 14 días
find "$BACKUP_DIR" -name "*.sql.gz" -mtime +14 -delete

echo "Backup completado: db_$DATE.sql.gz"
EOF
chmod +x /srv/control-actions/scripts/backup-db.sh
```
